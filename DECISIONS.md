# Decisions

- Removed the template Material theme (`ui/theme`); Material3 stays a dependency for the future debug panel only.
- Project lives in `C:\Users\mubar\AndroidStudioProjects\MyLiveRobot`; specs copied to `/specs`.
- Task 2: keep-screen-on is unconditional for now; the Sleeping-dim exception arrives with task 14.
- Task 3: glow is stacked translucent copies (10 layers, 3 units apart) instead of blur; cheap and safe on every GPU. Eye/mouth numbers moved into Tuning.
- Task 3 fix: face is centred on the full screen, not the cutout-safe area (cutout inset made it look off-centre). Revisit if a device cutout ever overlaps the face.
- Task 4: renderer draws through the native Android Canvas with reused Paint/Path objects (zero JVM allocation per frame). Lid/tilt cuts use `Path.op(INTERSECT)` so the glow follows the cut shape.
- Task 4: added `thick` and `spin` to EyeParams and `tilt` to MouthParams (spec 03 needs them). Fully closed RECT shrinks to a line as thick as the stroke.
- Task 4: TEMPORARY gallery toggle = tap anywhere. Replaced by the two-finger debug panel in task 11.
- Task 4 (Mubariz's call): Heart/Love mouth = small smile (new `MouthKind.ARC_SMILE`); Chevron/Denying mouth = zigzag (new `MouthKind.ZIGZAG`, w 140). This overrides the DASH for Love and Denying in spec 03; use these in `Moods.kt` (task 5).
- Task 5: moods are rows in `Moods.kt` (`Mood` enum + `MoodSpec`); `Moods.apply(face, mood)` copies a row into FaceParams in place. Full battery = Happy (no separate row). Wink's closed eye is ARC_UP, as on the sheet.
- Task 5: the `renderMood(mood): ImageBitmap` snapshot test hook from spec 03 is not built; the debug gallery (tap to cycle face, kinds, moods) covers visual checks. Revisit if automated snapshot tests are wanted.
- Task 5: Charging bolt glyph and glow pulse are deferred (tasks 9 and 15).
- Task 5 (Mubariz's call): LowBattery mouth = battery icon with one bar of charge (`MouthKind.BATTERY_LOW`, w 200), eyes stay half-lidded. Replaces the plain dash so the face is readable without explanation. A bar blink/flicker can be added in task 9.
- Task 5: Waking face is a placeholder; Mubariz wants to improve it through its animation (tasks 8/9/14).
- Task 6: frame loop uses `Choreographer.FrameCallback` (primitive Long, no boxing per frame) instead of `withFrameNanos`; the Canvas reads a `mutableLongStateOf` frame counter to redraw.
- Task 6: until the blink-swap (task 8), a mood switch changes eye/mouth *kinds* instantly while numbers ease, so some switches look odd (e.g. a spiral growing from RECT size). Expected.
- Task 6: TEMPORARY bottom strip of mood buttons plus a "Gallery" button replaces the tap-to-cycle gallery. Both go away with the debug panel (task 11).
- Task 6 perf check on the test phone (2340x1080): about 61 fps, jank ~0%, with 10 glow layers. `dumpsys gfxinfo` GPU percentiles were noisy (GPU clock scaling), so redo a profiler check on a mid-range device in task 16.
- Task 7: FaceAnimator now keeps `base` (mood layer, eased numbers) and `face` (what is drawn = base + look + blink + drift/breathing). New files: `Blinker.kt`, `LookWander.kt`, `Drift.kt`, each pure Kotlin with an injectable `Random` for tests.
- Task 7: LowBattery uses the Tired blink profile (spec says "slow tired blinks"); blinking is suppressed for 500 ms after a mood change (Tuning.BlinkSuppressAfterMoodMs) until gestures exist.
- Task 7: look wander applies to every eye kind except it is range 0 in Sleeping and Crazy; Wink's open eye and arc eye move together.
- Task 7: drift/breathing amplitude and period ease with tau 400 ms between moods, so entering Sleeping never makes the face jump.
- Task 8: blink-swap = eyes close 90 ms, kinds swap and numbers snap while closed, open 140 ms (easeOutBack for Surprised/Curious/Love, else easeInOutCubic). At the swap the mouth only snaps if its kind changes; otherwise its numbers keep easing.
- Task 8: renderer now allows eye `open` up to 1.25 (`Tuning.MaxEyeOpen`) so the easeOutBack pop is visible. Mouth-only kind changes cross-fade via `MouthParams.alpha` (60 ms out, 60 ms in).
- Task 8: mood requests within 400 ms of the last change are queued, latest wins; requesting the current mood cancels the queue. A blink already in progress is cut short when a change starts (rare, not noticeable).
- Task 9: per-mood idles live in `IdleMotion.kt` (pure Kotlin, tested) and are added on top of drift in `FaceAnimator`. Glow overrides (Charging, Low battery, Broken) blend in over 300 ms; Angry multiplies glow by 1.0..1.1.
- Task 9: added `MouthParams.dx` (Broken jitter) and `FaceParams.alpha` (Broken blackout, whole face).
- Task 9: not built: Wink's optional "right eye re-opens to RECT every 5 s". Denying stays static until the ShakeNo gesture (task 10). Sleeping entry/wake sequences stay with task 14.
- Task 9: Surprised ring pulse starts 250 ms after the mood starts, so it lands after the blink-swap has reopened the eyes.
- Wink idle (Mubariz asked for it, the optional row in spec 04): every 5 s the closed right eye closes, becomes the left eye's shape, opens for 400 ms, then closes and winks again. Left eye never changes. The cycle timer starts once the mood has fully arrived and resets if the mood changes. Replaces the earlier "not built" note for Wink.
- Wink re-open idle: disabled by default (Mubariz did not like it). Code stays; set `Tuning.WinkReopenEnabled = true` to bring it back.
- Task 10: gestures live in `GestureLayer.kt` (pure Kotlin, tested) and `FaceAnimator.play(gesture)`. Gesture faces (ShakeNo=Denying, Jolt=Surprised, GlitchBurst=Broken, Giggle=Happy, Yawn=Tired) appear instantly (no blink-swap) so the motion lands on time; the return to the previous mood uses the normal blink-swap. NodYes, Bounce and LookAround keep the current face.
- Task 10: a mood requested while a gesture face is showing is stored and applied when the gesture ends; blinking is off while a gesture runs. Gestures bypass the 400 ms mood-change gap.
- Task 10: TEMPORARY second row in the debug strip triggers each gesture. The strip overlaps the lowest part of the face; the hidden debug panel (task 11) replaces it.
- Task 11: hidden debug panel (`ui/DebugPanel.kt`). Two fingers held 1 s (moving less than 2x touch slop, exactly two pointers) open a side panel with: view (face / kinds / moods galleries), every mood, every gesture, fake battery (level + charging) and fake time sliders. It replaces the temporary bottom strip and tap-to-cycle gallery.
- Task 11: "debug builds only" is enforced at runtime with `ApplicationInfo.FLAG_DEBUGGABLE` (`DebugGate`), so no BuildConfig is needed and release builds never attach the gesture or compose the panel.
- Task 11: fake battery and fake time live in `DebugState` but nothing reads them yet; the BehaviorEngine uses them from tasks 14 and 15. "Force any state" is added with the BehaviorEngine (task 12). The panel's mood highlight shows the last mood forced from the panel.
- Task 11: `app/src/androidTest/.../DebugPanelTest.kt` (two-finger hold opens, short or 3-finger touch does not, buttons work) is written and compiles, but has NOT been run: the test phone (MIUI) refused the test APK with INSTALL_FAILED_USER_RESTRICTED.
- Task 12: `BehaviorEngine` (pure Kotlin, fake-clock tested) owns the base state (Awake, Sleeping, Charging, LowBattery), the reaction layer (`react(Reaction)` with priorities Glitch > Touch > Device > GestureTimer; equal priority newer wins; a dropped one never resumes; Touch-vs-Touch debounce 150 ms), mood drift and gesture timers. Touch, time-of-day sequences and battery reactions (tasks 13-15) are `Reaction`s built on `react()`.
- Task 12: Sleeping is overridden only by Touch/Glitch reactions; falling asleep drops Device and timer reactions. Sleep window 23:00-06:59, idle sleep 10 min, a touch in the window wakes for 3 min (tasks 14 adds the Waking/Happy/Tired sequences). The 07:00 wake-up currently just turns Awake.
- Task 12: mood drift = rest on Neutral 20-60 s, then hold a weighted pick (Neutral 50, Happy 15, Bored 15, Sceptic 8, Tired 8, Wink 4, shifted by time of day) for 10-40 s. Never Angry, Sad, Love, Surprised, Broken, Crazy or Denying. Drift stops while Charging, LowBattery or Sleeping.
- Task 12: timer gestures: LookAround every 90-180 s (45-90 s in the afternoon), Yawn about every 5 min after 21:00, Yawn every 60 s at battery <= 5% and not charging. They play on the current face (their reaction has no mood).
- Task 12: brightness output is only emitted on change (0.05 when asleep, -1 = give control back); `DimWhileSleeping` is the single flag (default true per spec).
- Task 12: wired into the app. Debug builds start on a fake 12:00 and fake battery off, so the real clock does not put the robot to sleep while developing (it is night for the tester); switch "Use fake time" off in the panel to use the real clock. Panel got an "Auto behaviour" switch, a live State/Reaction line, quick scenarios (Awake, Sleeping, Charging, Low battery) and "Touch (wake)". Any touch calls `noteInteraction` as a placeholder until task 13.
- Task 12: battery is not read from the device yet (100%, not charging) unless faked; `ClockSource` reads the real local time.
- Task 13: touch lives in `behavior/TouchInterpreter.kt` (pure Kotlin, fake-clock tested) and `ui/TouchInput.kt` (Compose forwarder). Reactions are data in `behavior/Triggers.kt`, built on `BehaviorEngine.react()`. A second finger cancels the touch so the two-finger debug hold never counts as a tap.
- Task 13: a lone tap waits 250 ms to see whether a second tap follows (so a double tap is not preceded by a Curious reaction). While Angry (rapid taps) or the glitch sequence runs, further taps are counted but cannot interrupt it. Rapid taps skip the 150 ms debounce (`Reaction.ignoreDebounce`) so they can follow quick taps.
- Task 13: new mood `WinkLeft` (mirror of Wink) for tapping the left eye ("swap sides"). The Giggle played on an eye tap keeps the wink face (`Step.keepFace`, `FaceAnimator.play(g, keepFace)`) instead of swapping to Happy.
- Task 13: held reactions (LongPress, Pet) last until release, capped at 30 s (`Tuning.HoldForever`) in case an up event is lost. Cancelling a hold (second finger) still plays the release reaction.
- Task 13: eyes follow the finger while petting and look toward the tap on a single tap: `LookWander.follow` clamps to 1.5x the idle ellipse and settles in about 120 ms (spring tau 40 ms). Swipes make the eyes snap toward the screen edge the swipe points at.
- Task 13: touching a sleeping robot plays Waking 600 ms then Curious (Tired inside the 23:00-07:00 window, per the time-of-day table); the touch that wakes it is not also a tap.
- Task 14: going to sleep (window start or idle sleep): eyes droop shut over 1.2 s (blink-swap with a slow close), Sleeping springs use tau 400 ms, and the glow fades over about 1.5 s starting immediately (glow now eases toward the NEW mood's glow from the start of every mood change, not after the swap). The screen dims only 1.5 s after sleep starts (`SleepDimDelayMs`), so the animation is seen at full brightness; waking restores brightness at once.
- Task 14: waking from Sleeping: the eyes open slowly (450 ms) onto the Waking face, which now starts with the eyes low and lifts them over 0.7 s (`IdleMotion`). Leaving Waking pops the eyes open from the sleepy half-open with easeOutBack (300 ms), also when the next face has a different eye shape. This is the "better Waking animation" Mubariz wanted; the Waking face itself is unchanged.
- Task 14: 07:00 wake-up: when the sleep window ends while the robot is asleep, the engine plays Waking 600 ms then Happy 8 s (Device priority), then Awake. It only plays if the clock lands in 07:00-07:30; jumping to e.g. noon just wakes it. The schedule counts as interaction, so idle sleep cannot keep the robot down after the window ends (it would otherwise stay asleep all day after a night without a touch). A robot already awake through a touch at 07:00 gets no sequence.
- Task 14: the debug panel has chips to jump the fake clock to 22:59, 23:00, 06:59, 07:00, 12:00.
